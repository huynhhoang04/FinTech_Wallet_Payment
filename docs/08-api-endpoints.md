# 08 — Danh mục toàn bộ API endpoint (REST · gRPC · Kafka · Actuator)

> Biên soạn trực tiếp từ mã nguồn nhánh `main` (ngày 2026-10-06). Gồm **tất cả** endpoint đang tồn tại:
> REST công khai qua gateway, REST nội bộ `/internal/**`, webhook đối tác, 8 RPC gRPC, 5 topic Kafka,
> 4 job định kỳ và endpoint hạ tầng (actuator, eureka).
>
> Format mỗi dòng API: **stt | service | endpoint | method | role | chức năng chi tiết | các hàm backend được dùng**.
> Mỗi hàm trong cột cuối: `path(file) | class | method | chức năng | tại sao cần`.

**Quy tắc viết path trong cột hàm** (rút gọn cho gọn bảng):

- `txengine/service/TransactionService.java` = `backend/transaction-engine/src/main/java/com/fintech/wallet/txengine/service/TransactionService.java`
- Tên module tương ứng package: `ledger`=account-ledger-service, `txengine`=transaction-engine,
  `payment`=payment-gateway-service, `notification`, `audit`, `common`, `gateway`=api-gateway.
- Ví dụ đầy đủ 1 entry: `backend/transaction-engine/…/controller/TransactionController.java` khi cần tuyệt đối.

**Cột Role — quy ước**

| Giá trị | Ý nghĩa |
|---|---|
| `PUBLIC` | Ai cũng gọi được, không cần JWT |
| `USER` | Bắt buộc Bearer JWT — gateway kiểm trước, service kiểm lại (role `USER` hoặc `ADMIN`) |
| `ADMIN` | JWT có claim `role=ADMIN` (chỉ audit-service phân role) |
| `INTERNAL` | Cần header `X-Internal-Token` (`/internal/**`) — gọi service-to-service |
| `PROVIDER` | Callback đối tác thanh toán — HMAC `X-Provider-Signature` |
| `SERVICE` | Kênh nội bộ giữa các service (gRPC / Kafka) |
| `PLATFORM` | Hạ tầng chạy trước mọi endpoint, không phải URL |

Header chuẩn (`common/constant/HeaderNames.java`): `X-Idempotency-Key`, `X-Internal-Token`,
`X-Signature` + `X-Timestamp` (HMAC gateway), `X-Provider-Signature`, `X-Request-Id`;
response replay thêm `Idempotent-Replay: true`.

## 6. Ghi chú kỹ thuật (đọc trước khi dán endpoint vào client)

1. **Lớp xác thực hai lớp**: client phải đạt **HMAC (G-1)** tại gateway **và** JWT (G-4, lại tại G-7 từng service). `/webhooks/**` miễn HMAC gateway nhưng tự verify HMAC provider; `/api/v1/auth/**` miễn JWT nhưng phải HMAC.
2. **Rate-limit theo route** (gateway `application.yml`): auth 1 req/s (burst 10) – chống brute force login; transactions 20 req/s (burst 40) + CircuitBreaker `transactionEngineCircuitBreaker`; payments 5 req/s (burst 10); accounts/notifications/webhooks không rate-limit riêng.
3. **Idempotency là bắt buộc** trên các endpoint: `POST /api/v1/transactions/{transfer,deposit,withdraw}` và `POST /internal/payments/intents` (header `X-Idempotency-Key`). Redis TTL 24h, key `idem:<key>`, conflict → 409 `IDEMPOTENCY_CONFLICT`, đang chạy → `DUPLICATE_REQUEST`.
4. **Endpoint ADMIN không qua gateway** — gateway dù `docs/02` không route `/api/v1/audit/**` + `/api/v1/reconciliation/**`; gọi trực tiếp `:8085` (hoặc qua mạng nội bộ/admin proxy), rate-limit không áp dụng ở tầng gateway cho các API này.
5. **Xuất hiện chưa chuẩn hoá (delta cần xem lại)**:
   - STT 18 — `/api/v1/transactions/internal/transactions/{id}`: comment code yêu cầu "behind the internal token" nhưng nó nằm dưới `/api/v1/**` (bảo vệ JWT, không có ownership check). Nếu mục tiêu là internal token, cần chuyển thành `/internal/transactions/{id}` để `InternalTokenFilter` (G-6) chặn.
   - STT 27 — demo simulate-callback mặc định BẬT (`matchIfMissing = true`): prod phải đặt `app.payment.demo-endpoints=false` (docs/07 SEC-01).
   - STT 49, 50 — topic `payment.webhook.received` và `audit.event` chưa có publisher.
   - Recipient notification luôn là `app.notification.demo-recipient` — gap nhận diện người nhận từ account (docs/07 ghi chú trong `NotificationService`).
6. **OTP**: challenge chỉ giữ in RAM trong 120s (single instance) — restart service mất các OTP đang phát; OTP token TTL 120s, có claim `otp=true`, dùng cho transfer/withdraw khi `amount > app.otp.threshold` (10.000.000).
7. **Role ADMIN thực tế** cấp từ `app.security.admin-phones` permit allowlist trong `AuthService.issueTokens` — schema users không có cột role (docs/07 SEC-03).
8. **Lỗi chuẩn** mọi REST: shape `docs/04-api-contract.md §0.4` — `401 UNAUTHENTICATED`, `403 FORBIDDEN`, `404 NOT_FOUND` (thường mask), `409 IDEMPOTENCY_CONFLICT`, `422 FRAUD_BLOCKED`, `429 rate-limit`, `503 UPSTREAM_UNAVAILABLE` (gRPC ánh xạ status `NOT_FOUND`/`FAILED_PRECONDITION`/`UNAVAILABLE`).
